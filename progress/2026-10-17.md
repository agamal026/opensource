## Tools and workflow added

- `oss_status.py`: validates the curated registry and complete snapshot, refreshes
  public PR metadata/checks, and renders deterministic Markdown. A failed query
  leaves the previous snapshot intact.
- `workspace_snapshot.py`: records Git branches, revisions, and change counts,
  including detached/unborn HEADs and partial failures, without exporting paths,
  filenames, remotes, diffs, or identities.
- `resume-open-source`: versioned continuation skill with source inspection,
  focused validation, publication, and handoff steps.
- Linux/Windows CI configuration, an improvement roadmap, and continuation/data
  guides. Local mappings remain ignored and survive repeated initialization.

## Validation performed

**48 offline tests passed on Linux**: 33 status-tool tests and 15 workspace tests.
The workspace tests create real temporary Git repositories. They cover staged
and unstaged changes, renames, conflicts, untracked files, detached/unborn HEADs,
and unchanged index bytes/mtime. Two POSIX-specific tests are intentionally
skipped by the configured Windows job.

The first live refresh exposed an installed GitHub CLI 2.46 limitation:
`gh pr view --json` did not export `baseRefOid`. The revised implementation uses
the CLI's generic GraphQL transport, requests explicit public fields, and
traverses all check-context pages. Regressions cover that compatibility case,
101 contexts with a failure on page two, changing head/base metadata, incomplete
pagination, unknown states, and atomic failure. The revised query still requires
a successful live CLI run; offline tests are not presented as that result.

The skill passed its frontmatter/name validator. A separate documentation review
checked commands, publication scope, and continuation behavior. It caught and
fixed configuration initialization that could otherwise overwrite saved mappings.
