## Checkpoint correctness fix

The old workspace parser silently accepted duplicate JSON keys. For example:

```json
{
  "schema_version": 1,
  "workspaces": [{"id": "important", "path": "missing-worktree"}],
  "workspaces": []
}
```

The later `workspaces` value replaced the earlier one. The command returned
success with `complete: true` and no checkouts, hiding the missing worktree.

The [fixed parser](../tools/workspace_snapshot.py) rejects duplicate keys at every
object depth before Git inspection. It reports the sanitized category
`duplicate_config_key` and returns 2. All configuration errors now preserve an
existing output file and avoid creating a new destination directory. Stdout
diagnostics, including `--output -`, remain available; valid partial snapshots
still report the unavailable checkout and return 1.

Three added [regression methods](../tests/test_workspace_snapshot.py) cover the
hidden-workspace case, nested selection keys, and output preservation for
duplicate keys, malformed JSON and unsupported schema versions. The regressions
failed against the old implementation. **All 51 tests passed on cloud Linux**
after the fix: 33 status-tool tests and 18 workspace tests. An independent static
review found no blocking issue and corrected the documentation of `--output -`.
